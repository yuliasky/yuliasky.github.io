In the rapidly evolving landscape of modern networking, the traditional approach to planning—often manual, siloed, and reactive—is becoming a significant bottleneck. As networks grow in complexity and scale, the need for a more dynamic, data-driven approach has never been more critical.

1 The Limitations of Traditional Planning

For years, network planning has relied on periodic analysis, manual data collection, and static modeling. While this served the needs of simpler architectures, it fails to keep pace with the demands of modern, high-capacity environments. The result is increased operational complexity, slower time-to-market, and missed opportunities for optimization.

2 The Shift Toward Autonomy

Autonomous network planning represents a fundamental shift. By moving away from manual interventions and toward a framework powered by intelligent automation, organizations can transition from "planning for today" to "predicting for tomorrow." This journey is built on three distinct pillars.

3 The Foundation: Simplifying Planning Today with Crosswork Planning

Before we can achieve full autonomy, we must master the fundamentals. Crosswork Planning (CP) serves as the cornerstone of this strategy. As a comprehensive automation application, it simplifies the complexities of network design, planning, and optimization right out of the box.

By providing a unified view of the network and advanced modeling capabilities, Crosswork Planning allows teams to: * Reduce Complexity: Visualize and manage multi-vendor, multi-layer network topologies with ease. * Optimize Resources: Identify bottlenecks and optimize traffic engineering paths before they impact the business. * Mitigate Risk: Perform "what-if" analysis to validate changes in a safe, simulated environment.

4 The Accelerator: Boosting Efficiency with CP APIs and Python SDK

While the Crosswork Planning application provides the essential tools for human-led planning, the next step in the evolution is programmatic scale. By leveraging our native Python SDK, organizations can move beyond manual workflows into the realm of automated network planning.

The Python SDK is a game-changer for customization; it allows engineers to build complex planning workflows using an intuitive, Pythonic syntax. This makes it easier than ever to integrate planning insights directly into CI/CD pipelines and operational systems. Beyond simple automation, these Python scripts serve as the essential tools for the next phase of our journey: the agentic future.

5 The Future: The Agentic Shift Toward Autonomy

The final evolution is the introduction of AI agents. If APIs provide the "hands" to execute tasks, AI agents provide the "reasoning" to make intelligent, context-aware decisions. However, agents are only as effective as the tools they are given.

By utilizing the Python scripts created in the previous step, we can provide AI agents with a library of actions to perform. To ensure success, we must define these tools with precision. Because ambiguity is the enemy of Large Language Models (LLMs), our tools are designed to provide outputs in a strictly structured format. This structured data ensures that the agent can interpret results accurately, enabling it to monitor the network, analyze trends, and proactively execute optimizations without human intervention. This is the key to managing massive network scale while augmenting your team’s operational capacity.

6 Technical Implementation: Building Your First Autonomous Agent

4.1 The Tooling Layer: Python SDK & Structured Outputs

To avoid the "ambiguity trap" with LLMs, every tool must return a strictly structured format (e.g., JSON).

Representative Tool Example:

def get_link_utilization(link_id: str):
    # Logic using CP SDK to query the network model
    return {
        "status": "success",
        "data": {"link_id": link_id, "utilization_pct": 75.5}
    }

4.2 Local vs. MCP: Choosing Your Tooling Strategy

  • Local Tools: These reside directly within the agent’s execution environment. Ideal for simple, dedicated agents where minimal latency is the priority.
  • MCP (Model Context Protocol): The industry standard for interoperability. By hosting tools on an MCP server, you decouple the tool logic from the agent, allowing the agent to discover and invoke tools dynamically.

Tool Definition Example (JSON Schema):

{
  "name": "get_link_utilization",
  "description": "Returns current utilization for a specific link.",
  "parameters": { "link_id": "string" }
}

4.3 Architecture Overview: Integration with the Crosswork AI Framework

Crosswork AI is a production-ready, multi-agentic framework that provides built-in Cisco agents while enabling users to onboard custom agents via the Crosswork AI Agent SDK (ADK). It is important to note that the following architecture represents prototype work and is not a productized CP agent. The integration relies on the following components:

  • CP Agent: A custom agent created using the Crosswork AI ADK and onboarded into the Crosswork AI framework to handle planning-specific reasoning.
  • LLM Proxy: Centralizes LLM interactions for governance and model flexibility.
  • MCP GW (Gateway): Facilitates the connection between the agentic environment and external toolsets.
  • CP MCP Server: Leveraging the CP SDK, this server acts as the dedicated interface for the CP Agent.
  • Crosswork Planning (CP) Server: The authoritative source of truth for network data, exposing the opm-service to interact with the powerful CP simulation engine.

7 Conclusion: The Future is Autonomous
